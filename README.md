# Mooncake Studio

Design mooncakes and matching printable molds in your browser. Upload black-and-white artwork, adjust the silhouette and relief, inspect the pastry and tooling, and export STL files in millimeters.

## [Open Mooncake Studio](https://jonzornow.github.io/mooncake-studio/)

The hosted app runs entirely in your browser; no application server or account is required. GitHub’s repository file viewer shows `Mooncake-Studio.html` as source code by design. Use the link above for the rendered application, or download the HTML file and open it in a desktop browser.

## Use

There are two distribution modes:

- **Hosted:** use the GitHub Pages URL shown in the repository's **Settings → Pages** after the included deployment workflow runs. No application server is involved; GitHub Pages serves the static browser build.
- **Offline:** download **Mooncake-Studio.html** and open it in a desktop browser. It embeds its scripts, artwork and geometry engine; no server, account or network connection is needed.

GitHub's repository file viewer displays or downloads source files; it does not execute this app. Source development uses the build commands below.

Click **Edit** to open the artwork-first popup. Sections collapse independently. Tap a mold inset to bring it into the main view. Save a project JSON before closing: changes are not automatically persisted. PNG, JPEG, WebP and vector-only SVG are supported; DXF must be converted externally. SVGs are rasterized at 384 px before contour tracing, so use broad black shapes on white. Raster uploads default to a shape-filling crop. Inputs are limited to 15 MB / 36 megapixels; projects to 4 MB / 25,000 points.

Select raised or recessed **on the finished cake**. The tool is complementary and mirrored automatically. Fillet and chamfer affect exported relief geometry. Applied rounding may be smaller than requested when artwork is thin. Engraved plates automatically retain at least 1.5 mm of solid backing; the separate blank pusher retains the chosen base thickness.

Export includes body, design plate, blank pusher, cake reference, project and validation data. Import into your slicer at 100%, millimeters. Print plates flat-back-down and fit-test altered profiles. The default is a nominal 45 mm channel, with configurable clearance. Cake volume is not a cake-weight rating.

## What the preview means

### Artwork library

**Edit Cake → Artwork** includes Rocket, Lotus Garden, Peony Scroll, Peach & Five Bats, Double Happiness and **Custom** (upload). The four traditional-inspired designs also appear in the guide. They use floral carving, auspicious symbols and scrolling foliage informed by photographs of molded cakes in the [Wikimedia Commons mooncake collection](https://commons.wikimedia.org/wiki/Category:Mooncakes). Except for the noted CC0 symbol, they are original vector interpretations rather than copies of a specific cake or historical mold. All five built-in assets are SVG paths, with no embedded bitmaps or font dependencies: `public/rocket.svg` and `src/art/*.svg`. Runtime contour tracing uses a temporary raster; the distributed source artwork stays vector.

Replacing custom artwork or unsaved work asks for confirmation. Save a project to retain editable settings. Unsaved changes request the browser's native close/reload warning; browsers, especially mobile ones, may suppress it. Do not rely on that warning as a backup.

README photographs live only in `docs/images/`; they are not embedded in the app or loaded by it. The standalone HTML intentionally duplicates bundled code so it can run without the source tree. Dependency folders, build intermediates and test artifacts are excluded from the source archive.

Pastry softness, browning, glaze and grain are appearance controls only. Exact geometry mode shows exported geometry. Fillets are faceted circular-profile relief edges, not analytic CAD surfaces. They round raised tips and complementary recessed floors. Design-wall draft defaults to 6° over a 3.5 mm pattern depth. **Preserve artwork outline** is on by default: the intended design is retained at the visible relief face and the walls grow outward toward the base. This can close small enclosed gaps below the face. Turning it off restores inward taper, which narrows the visible design. The successfully tested sleeve remains straight to preserve plate/pusher fit, and perimeter rims remain square. The available margin may limit the applied draft or fillet; the interface reports the actual result. The preview does not simulate dough flow, baking or release. Printer tolerances and real pastry behavior still require physical testing.

## Food-safety warning

Not all printing materials are food-safe. FDM layer lines can hinder reliable sanitation. This tool does not certify prints for food contact. Use at your own risk, verify every material and process used for food-contact applications.

## Mobile and browser status

See [BROWSER-COMPATIBILITY.md](BROWSER-COMPATIBILITY.md) for measured results and the remaining device checklist. Chromium and Firefox desktop automation passed; Safari on macOS passed a manual check; Chromium touch emulation passed for iPhone 13, Pixel 7 and iPad Mini presets. Physical mobile devices remain unconfirmed. WebGL 2, WebAssembly, workers, Canvas and native dialogs are required. Phones may take longer to rebuild complex artwork.

For phones, a static HTTPS page is the intended distribution route to test: upload `dist/` to static hosting, or serve the standalone HTML as a page. This requires no application backend. iPhone Files/Quick Look may decline to execute the JavaScript, WebAssembly or web worker in downloaded HTML; use the hosted page in Safari instead. Both builds include a plain startup message so a blocked or failed load does not appear as an unexplained blank screen. There is no service worker/offline cache for the hosted version.

## Develop and build

Requirements: Node 22.12+ (tested on Node 24), npm and Python 3.

```sh
npm ci
npm run dev
npm run build:standalone
npm test
npx playwright install --with-deps chromium firefox webkit
npm run test:browser
npm run test:mobile
```

`npm run build` creates `dist/` for static hosting, with relative asset paths. `npm run build:standalone` additionally creates root `Mooncake-Studio.html`. The wasm file is copied from the locked dependency before builds. Run browser tests with `BROWSER=firefox` or `BROWSER=webkit`; touch tests support Chromium and WebKit. `BROWSER_EXECUTABLE` can select a compatible local browser binary. Tests save reports and screenshots under `test-results/`. The included GitHub Actions workflow runs all three engines; it has not yet run in a repository.

## Publish on GitHub

Commit the complete repository, including the generated root **Mooncake-Studio.html**. Keep `node_modules/`, `dist/`, test output and the generated development copy of `public/manifold.wasm` untracked as specified by `.gitignore`.

The **Release checks** workflow validates pushes and pull requests. The separate **Deploy GitHub Pages** workflow builds `dist/` and publishes it whenever `main` changes. After the first push, open **Settings → Pages** and select **GitHub Actions** as the source if GitHub has not selected it automatically. The deployed site needs no backend or runtime secrets.

## Code map

- `src/main.js`: interface, project IO, worker scheduling and event-driven view rendering.
- `src/geometry.js`: solid construction, fit/retention validation and relief edges.
- `src/trace.js`: image loading, SVG screening and contour tracing.
- `src/pastry.js`: cosmetic pastry geometry/materials.
- `src/worker.js`: geometry worker, keeping modeling off the interface thread.
- `build_standalone.py`: offline packaging and embedded notices.

Views render on changes and pause when hidden. The application does not continuously animate idle scenes. Geometry builds and image decoding can still consume substantial CPU/memory.
